### Scan API contract (frontend already coded)

`GET /api/scan/processes` must 200 JSON:

```json
{
  "engine": "audio-guard",
  "threats": 0,
  "cleared": 0,
  "rows": [
    {
      "pid": "ag-1",
      "proc": "audio-guard",
      "target": "song.mp3",
      "state": "SCANNING"
    }
  ]
}
```

`state` MUST be one of: `SCANNING` | `TRANSCODE` | `WRITING` | `CLEAN` | `THREAT`  
(`App.jsx` colors those exact tokens.)

`pid` is a short id string (not necessarily an OS pid). `proc` + `target` are shown in SCAN PROCESSES.

When this route exists, App sets scan status online. Wire the Transfer Profile **Scan before transfer** switch: default **ON**, not disabled. When ON, `process_upload_job` scans each saved upload **before** ffmpeg; THREAT → that file does not transcode/transfer; if all files threat/fail → job `failed`; mixed → `partial` with log lines. When OFF, skip scanner (still allowed; log that scan was skipped).

Optional extra engine: if `MpCmdRun.exe` exists, run **only** on the dropped file path (`-Scan -ScanType 3 -File <path>`), timeout bounded (~30s). Missing Defender ≠ offline — heuristic engine still makes the service ONLINE.

### Audio scanner design (implement this, don’t invent a cloud AV)

Module: `backend/scan.py`. Public-ish API:

- `scan_audio(path: Path) -> ScanResult` with `ok: bool`, `state: str`, `reason: str`, `engine: str`
- In-memory recent rows for `/api/scan/processes` (thread-safe, cap ~50)

Checks (local, no network):

1. Size: reject empty / absurdly huge (e.g. > 500 MB per file)
2. Magic-byte allowlist vs extension: MP3/ID3/`FF FB`/`FF F3`/`FF F2`, `fLaC`, `OggS`, `RIFF....WAVE`, MP4 `ftyp` with M4A/M4B/mp41/isom/M4P, ADTS AAC. Unknown → THREAT (or at least fail closed for transfer)
3. Reject if file starts with `MZ`, ELF `\x7fELF`, Mach-O, `PK\x03\x04`, `%PDF`, `<html`, `#!` after skipping a valid ID3v2 tag
4. ID3v2: parse tag size, scan APIC/GEOB payloads for MZ/ELF/PK/PDF/HTML
5. After declared audio payload, reject a large trailing PE/ZIP/PDF appendix (polyglot)
6. Optional Defender file scan as above

**Tests** (`backend/tests/test_scan.py`): craft tiny fixtures in tmp (valid ID3+mpeg frame stub vs `MZ` + `.mp3` name vs ID3+APIC containing `MZ`). **Do not** add real malware, EICAR as a file in git is OK as a bytes literal in a test if you want Defender-path coverage, but keep it in the test module only.

THREAT must never call `add_tracks` — extend `test_main_cache.py` (or new test) with monkeypatched scanner.

Also add `GET /api/engine-busy` → `{ "busy": bool }` using `jsymphonic.wait_for_idle(timeout=0.05)` so Electron can refuse to quit mid-JAR rewrite (same idea as `launcher.py` `wait_for_transfer_finish`).
